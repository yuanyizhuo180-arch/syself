# Syself 目标路径卡片交互设计

日期：2026-09-04  
状态：已获交互方向确认，待用户审阅本说明

## 1. 目标

将目标工作树恢复为用户确认的「行动聚焦路径」视觉：深绿主目标位于路径顶部，当前月与周沿细线垂直生长，未来节点以右侧淡色卡片出现，底部以一组并列的三项今日行动承接当前周。

同时让可操作卡片在点击后平滑拉长，并在新增区域出现轻量的「编辑、完成、暂停」按钮。月目标、周目标和日任务都可被编辑、完成或暂停；主目标卡只展示方向，不承载这三个操作。

## 2. 布局与视觉基线

桌面端采用参考图的比例与阅读顺序：

```text
                        深绿唯一主目标
                              │
                  当前月目标 ── 未来月目标（淡化）
                              │
                  当前周目标 ── 未来周目标（淡化）
                              │
        路径说明 ─── 今日行动组：关键行动 / 支撑行动 / 支撑行动
```

- 主目标使用深松绿实底与暖白文字，宽度最大。
- 当前月、周是暖白细边框卡片，按月、周、日逐级收窄；连接线为低对比细线，并在当前节点交接处使用空心圆点。
- 未来月、周位于当前路径右侧，使用雾灰填充、虚线细边框与低对比文字；默认不展开内容，点击后才展开。
- 今日行动组横向排列三个任务卡，关键行动仅使用轻微的边框/底色差异，不使用左侧重色条。
- 小屏幕改为单列：未来节点排到当前节点之后，三项日任务垂直排列，不产生横向滚动。

## 3. 卡片展开交互

- 点击当前月、周或日任务卡的非按钮区域，卡片在 180–220ms 内向下拉长；再次点击同一卡片收起。
- 同一层级只保留一个展开卡片；展开新卡片时，同层已展开卡片收起，避免路径变成操作面板堆栈。
- 展开区域以 `max-height`、`opacity` 与短距离位移组合过渡；在 `prefers-reduced-motion: reduce` 下不播放过渡。
- 展开区域内的操作按钮必须阻止卡片点击冒泡，避免点击操作后立即收起卡片。
- 未来卡片继续由原生 `details/summary` 承担展开，且其内部操作仅在展开后出现。

## 4. 操作按钮

所有展开操作使用同一种次级按钮样式：透明背景、1px 细边框、12px 字号、400 字重、7px 圆角；悬停仅以浅灰绿背景和边框颜色变化提示可点击。不得使用绿色实底、白字、粗体，也不得用颜色作为唯一状态标志。

| 卡片 | 编辑 | 完成 | 暂停 |
| --- | --- | --- | --- |
| 月目标 / 周目标 | 复用现有内联目标编辑器 | 复用节点完成 API | 复用节点暂停 API |
| 日任务 | 在卡片展开区显示内联编辑字段 | 复用任务完成 API | 新增单任务暂停 API |

日任务编辑字段为标题、完成标准、最低行动和预计分钟数。保存后仅更新该任务并保留其 `work_node_id`、日期与所属周。日任务暂停将状态写为 `paused`，写入决策事件，保留在树的展开卡片中显示「已暂停」；不会暂停其周目标、不会影响同组另外两项任务。已暂停任务不计入「AI 已安排 N 项」。

## 5. 数据与接口

在现有任务字段上增加一个小型资源接口：

- `PATCH /api/tasks/[id]` 接收 `{ action: 'edit', title, completionCriteria, minimumAction, estimatedMinutes }` 或 `{ action: 'pause' }`。
- `edit` 校验四个字段均为有效值，更新 `task` 并记录 `decision_event` 的 `task_edited`。
- `pause` 将该任务状态更新为 `paused`，并记录 `task_paused`；任务状态类型增加 `paused`。
- `GET /api/goal-work-tree` 继续返回任务摘要，但状态联合类型补充 `paused`；暂停任务需要返回，供树显示历史与恢复上下文。
- `POST /api/tasks/[id]/complete` 保持不变；完成日任务后从当前行动组移除。

不新建任务副本、不修改 `work_node_id`，也不复用现有「暂停周目标」恢复动作来实现日任务暂停。

## 6. 前端边界

- `GoalWorkTree` 管理卡片展开标识和渲染；它通过 `onEditTask`、`onPauseTask`、`onCompleteTask` 向上报操作。
- 新增小型 `TaskCardEditor` 只管理一张任务的内联表单和校验，不承担数据请求。
- `GoalTreeClient` 是唯一的数据请求位置，负责乐观更新任务状态、处理错误并在失败时保留可编辑输入。
- 现有 `GoalNodeEditor` 不承担任务编辑，以免混淆月周与日任务字段。

## 7. 验收与测试

1. 当前路径符合参考图的主目标、当前月、当前周、右侧未来节点与下方三任务组层次。
2. 月、周、日任务点击后能展开与收起；操作区过渡在减少动效偏好下禁用。
3. 三类操作按钮均为透明、小字号、常规字重、细边框。
4. 日任务可编辑并刷新后持久化；完成和单任务暂停不会改变其他日任务或所属周目标。
5. 暂停任务不计入当日 AI 安排数量，但仍在树中可查看状态。
6. 新接口、目标树组件和客户端状态分别有失败先行的自动化测试；每次 TypeScript 修改后执行 `npm test`。
